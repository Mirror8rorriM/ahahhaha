# Как работает весь код ДЗ №2

## 1. Общая схема

В Shadertoy нет обычного игрового цикла на C++ или JavaScript. Каждый кадр платформа запускает
фрагментный шейдер для каждого пикселя. Точка входа — `mainImage(out vec4 fragColor, in vec2 fragCoord)`.
`fragCoord` — координаты текущего пикселя, `fragColor` — его результат.

В проекте два прохода:

1. **Buffer A** читает прошлое состояние и клавиатуру, рассчитывает новое состояние.
2. **Image** читает новое состояние Buffer A и рисует сцену.

Buffer A подключён к самому себе: он получает свой результат **предыдущего кадра**.
Image получает Buffer A **текущего кадра**. Без обратной связи углы и полёт снаряда не сохранялись бы.
Это не рекурсивный вызов: Shadertoy использует разные текстуры для чтения прошлого кадра и записи нового.

Оба файла — самостоятельные фрагментные шейдеры. `PI` и `sdBox` повторены намеренно,
чтобы не требовалась третья вкладка Common.

## 2. Типы, переменные и функции GLSL

- `float` — вещественное число; `int` — целое; `bool` — логическое значение.
- `vec2`, `vec3`, `vec4` — векторы из 2, 3, 4 вещественных компонентов.
- `.x`, `.y`, `.z`, `.w` выбирают компоненты, `.xyz` — первые три вместе.
- `ivec2` — пара целых чисел, здесь координаты текселя.
- `mat3` — матрица 3×3. `mat3(a, b, c)` записывает векторы в **столбцы**.
- `dot(a,b)` — скалярное произведение, `cross(a,b)` — векторное.
- `length(v)` — длина, `normalize(v)` — единичный вектор того же направления.
- `min`, `max`, `abs`, `sin`, `cos`, `tan` работают также покомпонентно с векторами.
- `clamp(x,a,b)` ограничивает значение диапазоном, `radians` переводит градусы в радианы.
- `texelFetch(texture, pixel, 0)` читает конкретный тексель уровня 0 без интерполяции.

Shadertoy предоставляет:

| Имя | Значение |
| --- | --- |
| `iResolution.xy` | Ширина и высота прохода |
| `iFrame` | Номер кадра, начиная с 0 |
| `iTimeDelta` | Время между кадрами в секундах |
| `iChannel0`, `iChannel1` | Подключённые текстуры |

`iTime` и `iMouse` игровым шейдерам не нужны.

## 3. BufferA.glsl — хранение и обновление состояния

### `PI`, `key`

`PI` используется для циклического ограничения азимута.
`key(code,row)` читает красный канал (`.r`) текстуры Keyboard.
Значение 1 означает активное состояние, 0 — неактивное.
Коды: 37 — влево, 38 — вверх, 39 — вправо, 40 — вниз, 32 — пробел.

Строка 0 Keyboard означает **удержание**, строка 1 — **нажатие в этом кадре**.
Для поворота нужно удержание, для одиночного выстрела — импульс нажатия.

### `sdBox`

Это signed distance function (SDF) прямоугольного параллелепипеда с центром в начале координат.
`size` задаёт **половины размеров**, например `vec3(1,2,3)` означает размеры 2×4×6.

```glsl
vec3 d = abs(p) - size;
return length(max(d, 0.0)) + min(max(d.x, max(d.y, d.z)), 0.0);
```

`abs` использует симметрию коробки относительно осей. Вычитание `size` показывает выход за её грани.
Снаружи `length(max(d,0))` даёт расстояние до ближайшей точки коробки.
Внутри первая часть равна нулю, а вторая даёт отрицательное расстояние до ближайшей грани.
На поверхности результат нулевой.

### `targetDistance`

Правый танк расположен в `(3,0,0)`. Вычитание этой позиции переводит мировую точку
в координаты танка. Затем считаются расстояния до корпуса и башни; `min` объединяет их.

Для башни мишени не нужен поворот в этой проверке: её азимут равен π, а прямоугольная коробка
симметрична относительно такого поворота. Возвышение меняет ствол, но не коробку башни.
Столкновения со стволом и гусеницами здесь не вычисляются — это упрощённая модель попадания.
Если последний кратер имеет тип 2, из объединения корпуса и башни вычитается сфера радиуса 0,35
с центром `crater.xyz`. Физика учитывает это углубление.

### Начало `mainImage`

`ivec2(fragCoord)` переводит центр пикселя в целочисленный индекс.
Используются только четыре текселя в нижней строке, остальные записывают нули и сразу завершают работу.
Выходные RGBA-компоненты здесь хранят числа состояния, а не видимый цвет:

| Тексель | Переменная | x | y | z | w |
| --- | --- | --- | --- | --- | --- |
| `(0,0)` | `control` | Азимут | Возвышение | Снаряд активен: 0/1 | Не используется |
| `(1,0)` | `shot` | Координата x | Координата y | Координата z | Возраст снаряда |
| `(2,0)` | `velocity` | Скорость x | Скорость y | Скорость z | Не используется |
| `(3,0)` | `crater` | Центр x | Центр y | Центр z | Тип: 0 нет, 1 земля, 2 танк |

Все четыре значения сначала читаются из прошлого кадра. Каждый из четырёх выходных пикселей
выполняет один и тот же расчёт, а в конце сохраняет только соответствующий ему `vec4`.
Поэтому нет зависимости от порядка выполнения фрагментов.

### Инициализация

На `iFrame == 0` азимут равен 0, возвышение — 12°, флаг активности — 0,
позиция, скорость и данные воронки обнуляются. Поворот 0 означает, что орудие смотрит вдоль +X.
Сброс времени Shadertoy повторно запускает эту ветку.

### Управление углами

```glsl
float dt = clamp(iTimeDelta, 0.0, 0.05);
control.x += (key(37, 0) - key(39, 0)) * dt * 0.85;
```

Влево даёт +1, вправо −1; вместе — 0. Скорость башни — 0,85 рад/с.
Умножение на `dt` связывает поворот с временем. На обычной частоте кадров он не зависит от FPS.
Ограничение 0,05 с защищает от скачка после паузы; ниже 20 FPS симуляция замедляется.

```glsl
control.x = mod(control.x + PI, 2.0 * PI) - PI;
```

Переносит азимут в диапазон `[-π, π)`. Полный оборот не меняет ориентацию.
Возвышение аналогично меняется вверх/вниз со скоростью 0,5 рад/с,
но `clamp` ограничивает его между 2° и 65°.

### Движение снаряда

`control.z > 0.5` означает, что снаряд летит.
Кадр делится на 8 подшагов: `h = dt / 8`. Это снижает риск пропустить мишень
между двумя проверками при низкой частоте кадров.

```glsl
shot.xyz += velocity.xyz * h + vec3(0.0, -0.5 * 9.81 * h * h, 0.0);
velocity.y -= 9.81 * h;
shot.w += h;
```

Используются формулы равноускоренного движения:

```text
p_new = p_old + v_old * h + a * h² / 2
a = (0, -9.81, 0)
v_new = v_old + a * h
```

Сначала позиция обновляется со **старой** скоростью, затем изменяется скорость.
Горизонтальные компоненты постоянны, вертикальная уменьшается под действием гравитации.
Размеры сцены и скорость условно интерпретируются в метрах и метрах в секунду.

Если `groundDistance(shot.xyz, crater) <= 0.1`, сфера радиуса 0,1 коснулась земли
с учётом существующей воронки. Тогда точка удара по XZ сохраняется в `crater`, Y центра ставится в 0, флаг — в 1.
Если `targetDistance(shot.xyz, crater) <= 0.1`, она коснулась корпуса или башни мишени.
В этом случае сохраняются мировые координаты снаряда и тип кратера 2.
В обоих случаях флаг активности обнуляется. Ограничение возраста 8 с убирает слишком долгий полёт.
`break` в начале следующего подшага прекращает расчёт уже неактивного снаряда.

### Создание выстрела

Выстрел разрешён, только если в этом кадре нажат пробел и другой снаряд уже не летит.
Направление строится из азимута `yaw` и возвышения `pitch`:

```text
direction = (cos(pitch) cos(yaw), sin(pitch), -cos(pitch) sin(yaw))
```

При нулевых углах получается `(1,0,0)`. Положительное возвышение поднимает Y.
Положительный поворот вокруг Y переводит +X в сторону −Z — отсюда минус у третьей компоненты.
Этот единичный вектор совпадает с направлением ствола после его кватернионных поворотов.

Точка подвеса орудия игрока — `(-3,1.37,0)`.
Начальная позиция — эта точка плюс `direction * 1.85`, то есть у конца ствола.
Начальная скорость — `direction * 9`. Возраст обнуляется, активность устанавливается в 1.
Затем состояние сохраняется в четыре текселя для следующего кадра и Image.

## 4. Image.glsl — отрисовка

`control`, `shot` и `crater` — глобальные переменные только внутри одного запуска фрагмента.
Их значения каждый раз загружаются из Buffer A. Это не самостоятельная память между кадрами.

### `axisAngle`

Слайды 14–16: единичный кватернион вращения вокруг оси `u` на угол θ:

```text
q.xyz = normalize(u) * sin(θ/2)
q.w   = cos(θ/2)
```

В презентации скалярная часть может записываться первой, а здесь она находится последней:
порядок `(x,y,z,w)`. Оси вызовов — единичные Y и Z, поэтому нулевой оси не возникает.

### `qMul`

Произведение Гамильтона двух кватернионов `(v_a,w_a)` и `(v_b,w_b)`:

```text
v = w_a v_b + w_b v_a + cross(v_a, v_b)
w = w_a w_b - dot(v_a, v_b)
```

Порядок существенен. При преобразовании вектора произведением `qYaw * qPitch`
сначала действует правый поворот `qPitch`, затем `qYaw`.
Композиция единичных кватернионов снова является единичным кватернионом
с точностью до ошибок вычислений.

### `toLocal`

Для SDF удобнее повернуть проверяемую точку в обратную сторону, чем поворачивать саму фигуру.
Для единичного `q` обратный кватернион — сопряжённый `(-q.xyz,q.w)`.
В функции `v = -q.xyz`, после чего используется сокращённая формула:

```text
rotated = p + 2 * cross(v, cross(v,p) + q.w*p)
```

Она эквивалентна `conjugate(q) * (p,0) * q`.
Сначала вычитается положение центра детали, затем применяется обратный поворот.
Это переводит мировую точку в локальные координаты детали.

### `sdBox`, `cylinderX`, `nearer`

`sdBox` — та же функция расстояния до коробки, что в Buffer A.
`cylinderX` считает расстояние до конечного цилиндра вдоль оси X:
`abs(p.x)-halfLength` измеряет выход за торцы, `length(p.yz)-radius` — за боковую поверхность.
Их объединение учитывает расстояние также возле рёбер торцов.

`nearer` сравнивает две пары `(distance, materialId)` и возвращает пару с меньшим расстоянием.
Так строится объединение объектов и сохраняется материал ближайшей поверхности.

### `tank`

1. `p -= center` переводит точку в координаты танка.
2. Корпус — коробка с центром `(0,0.63,0)` и полуразмерами `(1.12,0.43,0.72)`.
3. Цикл со `side = -1, +1` добавляет две коробки-гусеницы на `z = ±0.78`.
   Их центр по Y — 0,34, полуразмеры — `(1.20,0.28,0.19)`.
4. `yawQ` задаёт вращение вокруг Y. Для башни точка относительно центра `(0,1.27,0)`
   переводится функцией `toLocal`, после чего проверяется обычная коробка.
5. Для ствола `qMul(yawQ, axisAngle(Z,elevation))` объединяет возвышение вокруг локальной Z
   и азимут вокруг Y. Поворот вокруг Z поднимает исходное направление +X к +Y.
6. Ствол — цилиндр с локальным центром `(1.05,0,0)`, полудлиной 0,79 и радиусом 0,09.
   Он тянется от `x=0.26` до `x=1.84` относительно точки подвеса.

Для второго танка при `crater.w > 1.5` из объединения видимых деталей вычитается
сфера радиуса 0,35: `result.x = max(result.x, 0.35 - length(worldPoint - crater.xyz))`.
Координаты кратера мировые; мишень неподвижна, поэтому перевод в локальные координаты не нужен.

Корпус не поворачивается вместе с башней. Башня использует только азимут,
ствол — азимут и возвышение. Гусеницы и ствол получают тёмный материал.

### `scene`

Возвращает расстояние до всей сцены и ID материала.
Земля задаётся `groundDistance(p, crater)`: это плоскость `y=0` с одной вырезанной сферой при наличии воронки.
Первый танк стоит в `(-3,0,0)` и читает углы игрока.
Второй — в `(3,0,0)`, его башня повёрнута на π (к игроку), ствол поднят на 8°.

Если снаряд активен, добавляется сфера радиуса 0,1:
`length(p - shot.xyz) - 0.1`.
Все фигуры объединяются последовательными вызовами `nearer`.

### `normalAt`

Для освещения нужна нормаль к поверхности. Для SDF она направлена вдоль градиента расстояния.
Производные приближённо вычисляются центральными разностями:

```text
n.x ≈ distance(p + εX) - distance(p - εX)
n.y ≈ distance(p + εY) - distance(p - εY)
n.z ≈ distance(p + εZ) - distance(p - εZ)
```

`ε = 0.001`. Общий множитель `1/(2ε)` не нужен: вектор затем нормализуется.
`e.xyy`, `e.yxy`, `e.yyx` — сокращённые записи `(ε,0,0)`, `(0,ε,0)`, `(0,0,ε)`.
На рёбрах коробок нормаль может быть неоднозначной, что нормально для такой простой модели.

### `material`

Присваивает постоянный RGB-цвет по ID: 0 — земля, 1 — зелёный танк,
2 — коричневый танк, 3 — тёмные гусеницы и стволы, 4 — жёлтый снаряд.
Дробные пороги удобны для сравнения целочисленных по смыслу ID в `float`.
Никаких текстур и процедурного камуфляжа нет.

### Камера в `mainImage`

Сначала читаются состояние, позиция снаряда и данные воронки.

```glsl
vec2 uv = (2.0 * fragCoord - iResolution.xy) / iResolution.y;
```

Центр экрана становится `(0,0)`, вертикальный диапазон — примерно `[-1,1]`.
Деление обеих компонент на высоту сохраняет пропорции: горизонтальный диапазон
равен `[-aspect,aspect]`, где `aspect=width/height`.

Камера находится в `(8,6,10)` и смотрит в `(0,0.65,0)`.
`forward` — единичное направление к этой точке.
`right = normalize(cross(forward, worldUp))` даёт направление вправо.
`up = cross(right,forward)` восстанавливает перпендикулярное направление вверх.
Для выбранного положения камеры `forward` не параллелен `worldUp`, поэтому базис определён.

```glsl
mat3(right, up, forward) * normalize(vec3(uv * tan(radians(48.0) * 0.5), 1.0))
```

В локальных координатах камера смотрит вдоль +Z. `tan(FOV/2)` задаёт масштаб
виртуального экрана, FOV равен 48° по вертикали. Нормализация создаёт единичный луч.
Умножение на матрицу переводит его в мировой базис.

Это связь с матрицами вида и перспективы со слайдов 29–41:
в обычном рендеринге мировая вершина переводится к экрану, а здесь из экранного пикселя
строится мировой луч. Отдельные 4×4 view/projection-матрицы и преобразование глубины NDC
для данного алгоритма не требуются. Quaternion SLERP также не требуется, поскольку нет интерполяции поз.

### Поиск поверхности: ray marching

Цвет по умолчанию — однотонное небо. Для каждого пикселя запускается цикл до 150 шагов.
На шаге проверяется точка:

```text
p = camera + ray * distanceAlongRay
```

`scene(p)` возвращает расстояние до ближайшей фигуры.
Если оно меньше `0.0015`, поверхность найдена.
Иначе расстояние вдоль луча увеличивается на найденное расстояние до сцены.
SDF позволяет делать большие безопасные шаги вдали от объектов и маленькие рядом с ними.
При удалении дальше 60 единиц цикл останавливается и остаётся цвет неба.
Предел числа шагов защищает от бесконечного цикла и ограничивает стоимость пикселя.

### Простое освещение и результат

Свет направлен в сторону нормализованного `(-0.6,1,0.5)`.
`dot(normal,light)` — косинус угла между нормалью и направлением к свету.
Отрицательные значения обрезаются нулём: обратная сторона прямого света не получает.

```glsl
color = material(hit.y) * (0.3 + 0.7 * diffuse);
```

0,3 — постоянная подсветка, чтобы детали не становились полностью чёрными;
0,7 — вес диффузной составляющей Ламберта. Теней и бликов здесь нет.
`fragColor = vec4(color,1)` записывает непрозрачный цвет пикселя.
После этого Shadertoy показывает результат прохода Image на экране.

## 5. verify.py — отдельная проверка, не часть шейдера

Этот файл нужен разработчику для воспроизводимой проверки без аккаунта Shadertoy.
В редактор сайта его вставлять не нужно.

- `Path(__file__)` находит папку с шейдерами; `json` форматирует отчёт.
- `shutil.which` ищет Chromium. Playwright запускает его без окна с программным WebGL через SwiftShader.
- Временная HTML-страница содержит один canvas. JavaScript внутри `page.evaluate` получает WebGL 2
  и проверяет поддержку float-буферов `EXT_color_buffer_float`.
- `prefix` объявляет стандартные uniform-переменные Shadertoy и выходной цвет.
- `shader` компилирует GLSL и выдаёт ошибку компиляции; `program` линкует программу
  с общим вершинным шейдером и обёрткой `main`, вызывающей `mainImage`.
- Вершинный шейдер по `gl_VertexID` создаёт один большой треугольник, закрывающий canvas.
- `texture` создаёт две RGBA32F-текстуры для прошлых/новых состояний и RGBA8-текстуру клавиатуры 256×3.
- `fbo` — framebuffer для вывода в текстуру. `current` выбирает текущее состояние,
  `frame` имитирует номер кадра Shadertoy.
- `bind` связывает sampler с номером texture unit. `uniforms` передаёт разрешение,
  время, номер кадра, текстуру состояния и клавиатуру.
- `step(down,press)` заполняет строки клавиатуры, запускает Buffer A в другую текстуру,
  переключает `current` и читает четыре RGBA-текселя в 16 чисел для проверки.
- `render` запускает Image на экранном framebuffer и проверяет ошибки WebGL.
- `assert` прерывает проверку при неверном результате.
- `reset` ставит кадр в 0 и выполняет инициализацию через сам Buffer A.
- Последовательности кадров проверяют четыре стрелки, пределы угла, выстрел,
  гравитацию, исчезновение при попадании в танк и землю, отсутствие автострельбы,
  а также повторный выстрел после нового нажатия пробела.
- Проверка цветов читает результат Image и убеждается, что на нём достаточно зелёных
  и коричневых пикселей: это проверка видимости обоих танков, а не только компиляции.
- После проверок формируется кадр с воронкой, Playwright сохраняет `preview.png`.
  Отчёт печатается в терминал, браузер закрывается. Ошибка любого утверждения приводит к ненулевому коду Python.

## 6. Границы реализации

Управляется один танк, второй служит неподвижной мишенью. Урон, разрушение, движение корпуса,
взрывы и интерфейс не нужны для обязательной части задания и отсутствуют.
Одновременно активен один снаряд. При попадании он исчезает.
Модель столкновений включает землю, корпус и башню второго танка, но не его мелкие детали и не танк игрока.
Подшаги повышают надёжность дискретной проверки; это не точное непрерывное обнаружение столкновений.


## 7. Один последний кратер на земле или танке

Восстановлена простая схема с четырьмя текселями и двумя проходами, без Common,
массива кратеров, счётчика, ID деталей и накопления истории попаданий.

`crater.xyz` хранит один центр в мировых координатах. `crater.w` задаёт тип:
0 — кратера нет, 1 — земля, 2 — второй танк.

При ударе о землю записывается `(shot.x, 0, shot.z, 1)`.
При ударе о корпус/башню мишени записывается `(shot.xyz, 2)`.
Каждая новая запись заменяет предыдущую: одновременно есть только один кратер.
Между попаданиями он остаётся видимым до следующего попадания или сброса времени.

Для земли `groundDistance` возвращает `p.y`, если тип не равен 1.
Иначе из земли вычитается сфера радиуса 0,8 с центром на 0,4 выше `crater.xyz`:

```glsl
float sphere = length(p - (crater.xyz + vec3(0.0, 0.4, 0.0))) - 0.8;
return max(p.y, -sphere);
```

Для танка применяется тот же принцип CSG-разности, но радиус равен 0,35,
а центр соответствует позиции центра снаряда при контакте.
Сфера частично выступает за поверхность и вырезает углубление в корпусе/башне.
Image вычитает её из видимого второго танка, Buffer A — из модели столкновений корпуса и башни.
Первый танк остаётся без изменений, как в прежней простой версии.

`max(A,-B)` означает вычитание объёма B из A. `normalAt` уже обращается к изменённой `scene`,
поэтому нормали и освещение кратера пересчитываются автоматически.
Модель столкновений и видимая модель различаются мелкими деталями: ствол и гусеницы
не входят в проверку попаданий, как и в исходном варианте.

Проверочный скрипт проверяет кратер на танке и изменение изображения после попадания,
замену этого кратера попаданием в землю, сохранение единственного следа между кадрами,
столкновение внутри наземной воронки и очистку при сбросе.
